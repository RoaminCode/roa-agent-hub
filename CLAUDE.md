# ROA Agent Hub

Basecamp is ROA's Google Chat app. This repo is the hub behind it: the router that receives Chat messages and picks an agent, the tools that read LightSpeed and HubSpot, the rules that limit what agents can do, the schedules, and the logs. Today each AI job is a direct Messages API call with its instructions in `src/agents/`; Anthropic Managed Agents is the plan for when other agents and tools are added (Blake's call, 2026-11-07). Either way, everything agents can see and do runs through this hub. The first agent is the RJB (Roamer Journey Brief) agent.

## Session start and wrap

- **At the start of every session, read `HANDOFF.md` before doing anything else.** It holds the current state, current decisions, and next steps. Treat it as the source of truth over anything recalled from earlier sessions.
- **At session wrap, when asked, update `HANDOFF.md`:**
  - Update "Where things stand" and "Next steps" to match what actually happened this session.
  - Add new decisions to "Current decisions".
  - When a decision is replaced, **delete the old one**. Do not leave it with a pointer to the new one ("see below", "replaced by"). If deleting would lose context someone still needs, move it under "Retired, do not use" instead. Nothing under that heading is ever acted on.
  - Keep it short, about 120 lines. It is a snapshot of now, not a history; git holds the history. Detail that stays true (how a feature works, an API's quirks, a rule set) goes in the matching file under `docs/reference/`, with a one-line decision in `HANDOFF.md`.
- **`docs/reference/` holds the stable detail** (features, deal spaces and routing, the clock, App Home, HubSpot, Aloware, Google Chat). Read the file for the area a piece of work touches before changing it; do not load them all at session start.

## Rules

- **No real Roamer data in this repo.** Raw LightSpeed exports stay in `G:\My Drive\Service Management\RJB`. Test fixtures must be scrubbed (fake name, VIN, customer and deal numbers).
- **LightSpeed is the source of truth for deal facts.** Agents never edit HubSpot fields or LightSpeed. They write HubSpot notes, on the Roamer's contact and the deal's Delivery record, never on the deal (Blake's call, 2026-11-07), and one other thing: when a deal space opens, Basecamp finds the deal's Delivery record, or creates it (Delivery Pipeline, stage Deposit Received, and its Name and Trailer from the deal's name; nothing else filled) and links it to the deal and the Roamer (Blake's call, 2026-11-07). Stage moves stay proposed by the agent and confirmed by the owner.
- **Podium is fully retired.** Never mention it, suggest it, or read from it. HubSpot is the source of truth for Roamer communication. HubSpot is the record of all communication; Aloware is integrated into HubSpot and logs every text there. The hub may call Aloware for exactly one thing, sending a message a Team Member approved (authorized by Blake 2026-10-28; built in `src/aloware.js`, the only file that reaches Aloware), always as the company (`user_id: -1`), never as the default contact owner or another user, with a HubSpot note naming who approved it. Anything else in Aloware only when Blake explicitly says so.
- **Say "Service Advisor", never "Service Writer"**, even where older HubSpot properties or skills still say Writer.
- **Say "HubSpot task", never just "task",** when meaning a HubSpot task. The agent's own background work is a "run".
- **No HubSpot tasks** unless Blake decides otherwise. Basecamp keeps its own clock; accountability lives in deal space notifications.
- **Nothing reaches a Roamer or Future Roamer without a Team Member's approval of that exact message.** Agents draft. The approval shows the recipient's name and number and the exact text, covers only that one draft, and is logged. Approved messages go through Aloware's API, which logs them to HubSpot. The approval dialog also says the send is live and requires the approver to tick that they checked the number. Ad hoc test sends are never a substitute for this path. Agents never send on their own.
- **Shadow mode until Blake says otherwise:** every routed question, nudge, and draft goes to Blake, labeled with who it would have gone to, and nothing is sent to a Roamer. One exception, Blake's call (2026-11-07): approved texts are live (`TEXTS_LIVE=true`), so a text a Team Member approves in the dialog goes to the Roamer. Turning `TEXTS_LIVE` off stops all sends. What is shadowed is an answer to a question and a nudge. Not shadowed, each Blake's call: `/new` and `/wow` post in the space they were asked in (they summarize the record), a `/text` draft goes to whoever asked for it, and a person's own `/remind` goes to that person.
- **Prove before trusting the agent.** Deal spaces and deal watches may be built before the agent answers questions; they work without AI. The agent answers questions in deal spaces only after its answers are proven correct against LightSpeed in shadow mode. The delivery clock (touchpoints) may be built now, in shadow mode (Blake's call, 2026-11-07: its dates are in HubSpot, written there by LightSpeed, so there is nothing to prove first).
- **Basecamp creates nothing at deposit: no space, Delivery record, welcome, or profile.** Deal watches may count time from the deposit date. The first touchpoint (welcome draft and Roamer profile) happens on demand, when a Team Member opens the deal space from the Chat app; that same step finds or creates the Delivery record. Never describe a space, a Delivery record, a welcome, or a profile as starting at deposit, even where the RJB Agent Spec or older notes say so (Blake's call, 2026-11-07). Do not build HubSpot structure changes until the agent is proven. Push back if asked to skip ahead.
- **Basecamp helps Team Members; it does not reprimand them.** Escalation wording is deliberately undefined until designed with Blake. Follow-ups are logged for coaching.
- **Everything Basecamp can write, and the one file that does each:** HubSpot notes on the Roamer and the Delivery record, a deal's Delivery record, and a note's link to it (`src/hubspot/client.js`, four methods, nothing else); an approved text (`src/aloware.js`); rows and counts in the ROA WOW Ideas sheet (`src/wowLibrary.js`); Chat spaces and members (`src/chat/spaces.js`); Chat messages (`src/chat/send.js`); its own Firestore records (`src/db.js`). A new kind of write is a decision for Blake, not a code change.
- ROA language applies in all code comments, messages, and docs: Roamers, Future Roamers, Team Members, Sales Coach, Experience Center, Leader. No em or en dashes.
